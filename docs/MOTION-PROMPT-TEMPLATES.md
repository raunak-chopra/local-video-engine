# Reusable video direction prompts

These are original house templates for any agent using this repository. Replace
bracketed values with real information. They complement the active schema and
[shared playbook](MOTION-DIRECTION-PLAYBOOK.md); they do not authorize a new
renderer, purchase, upload, publishing action or invented facts.

## Exploration

```text
Read AGENTS.md, docs/CURRENT-TASK.md and docs/MOTION-DIRECTION-PLAYBOOK.md.
Make a [duration / canvas] video for [audience] that communicates [one takeaway].
Use [approved content / source paths]; the sound policy is [policy].
Suggest three distinct visual directions with an opening, meaningful progress,
payoff and a small motion vocabulary. Explain what each movement communicates.
Select the strongest direction against the viewer task and document assumptions.
Continue with a representative scene and actual frame review within the already
authorized work, unless I explicitly ask for a choice gate.
```

## Directed production

```text
Work in the existing local Remotion engine. Read the shared entry files first.

Purpose and viewer: [what someone should understand, feel or be able to do].
Output: [canvas, fps, approximate duration, scripts, sound policy].
Approved content: [facts, copy, recipe / product evidence, asset and source ranges].
Unknowns: [what must remain draft or cannot be inferred].
Visual thesis: [a concrete metaphor or relationship that supports the purpose].
Look: [palette roles, fonts, type hierarchy, alignment and reference properties].
Motion: [a small purposeful vocabulary and specific exclusions with reasons].
Timing: [opening, progression, reading holds, payoff; beat provenance if supplied].
Continuity: [cut / persistent-object rationale / optional loop intention].
Revision scope: [what may change and what approved content/timing must remain].

Save brief.md and, where useful, strict direction.json beside project.json.
Generate video plan. Implement only supported fields or a small typed extension.
Render a representative scene, inspect the actual frames, then expand.
Keep media local. Run npm.cmd run validate. Review boundaries, settled copy,
longest text and final frame in every requested canvas. Report implemented,
structurally verified, visually reviewed, playback, sound and phone checks
separately. Fix observed defects; leave unperformed checks explicitly pending.
```

## Faceless cooking adaptation

```text
Also read docs/REEL-PLAYBOOK.md and docs/REELS-FINAL-UPDATE-PLAN.md.
Use my selected Android footage for a [30–60 s recipe / 3–10 s mini-story].
No narration. Use [Hindi / Hinglish / English] copy based on supplied recipe facts.
Propose a relevant opening and make its payoff traceable to the source footage.
Cut by understandable action; preserve a useful technique and sensory payoff.
Use music alignment and reaction accents only when they serve that story.
Keep important text clear of the actual platform UI and inspect mixed-script
shaping. If a required overlay or audio feature is still unbuilt, say so and
implement the next bounded dependency in the governing plan; do not pretend a
graphic card over empty background is an on-footage ingredient overlay.
```

## Reference translation

```text
Study [reference] for framing, hierarchy, spacing, rhythm, continuity and sound.
Separate observed properties from inferred technique and unverified metadata.
Choose the few properties useful for this video's audience and explain why.
Map each chosen property to a current engine capability or a bounded extension.
Preserve our renderer, typed timing, local asset pipeline and factual content.
Do not infer rights to reuse the reference's footage, music, branding or source.
Make an original representative scene and inspect it before scaling the idea.
```

## Evidence-based revision

```text
Read projects/[id]/brief.md, project.json, direction.json if present, and
review-notes.md. Inspect [actual artifact / frame / time].
Observed defect: [what the viewer sees or hears].
Desired result: [a concrete observable change].
Preserve: [approved source ranges, copy, body timing, sound policy and style].
Repair the smallest cause, update the project/plan together if timing changes,
and render fresh evidence at the defect and neighboring boundaries.
Run the appropriate checks and record exactly what was reviewed.
Do not mark full-speed, listening or phone review complete from still images.
```
